Overview of the project structure:
backend/         - contains backend logic and routes
  routes/        - contains route definitions for API endpoints, these are used to keep (accesspoint)
                  app.py clean(these could have been in app.py, but for better    
                  organization we separate it out, to not make the file too big)
    api_auth.py         - Authentication related API-endpoints
    api_data.py         - data related API-endpoints

   services/     - contains business logic and service layer code(funcktion)
    database_logic.py   - contains all functions based on queries within DB_Read and DB_Write. This includes the business logic (rules) of queries
    llm_tools.py        - contains specifications of functions which the AI/LLM needs to call upon in a language it understands.
    notification.py     - writes a notification, either as a test or through email based on true/false statement. 
    weather.py          - weather based functions, based on API call to DMI.


 database/  contains the access to the database
 This folder is handles the database layer, this means that the files handel:
    - connection-DB_access. 
    - SELECT queries from the database- DB_read
    - GET queries from the database - DB_write


These files don't handle anything but database aspects,
basicly only things to do with workbench



 frontend/        - contains HTML, CSS, JS for the web interface
                   The .js files handle the frontend logic and interact with the backend API endpoints defined in backend/routes/
                   making the app dynamic and responsive, without having to reload pages all the time.
 app.py           - main Flask application file
 LLM_main.py      - main LLM integration file
 tests/           - contains unit and integration tests
